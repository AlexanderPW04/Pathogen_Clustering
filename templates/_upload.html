Pooled results are uploaded after sequencing reads were aligned to a reference and variants were called elsewhere. This website analyzes those processed results; it does not accept raw FASTQ reads or call variants.

Cross-source matching needs both sources on the same verified reference: the pooled table must name the uploaded reference (same ID and bases). Otherwise each source is still analyzed, but their variants are marked incomparable.

Which files do I need?

Individual sequence analysis (Sprint 2)
  • Required: a FASTA file of sequences (example) and a metadata table with an Accession (matching the FASTA names) and the Pathogen (example).
  • Optional: collection dates, locations or coordinates, and a reference genome FASTA (see "What optional information unlocks").
  • Result: MAFFT alignment, genetic p-distances, date and distance screening, and related-sample candidates.
Pooled sequencing analysis (Sprint 3)

A processed SNV table is the result of sequencing a pooled sample; this website starts there.

  1. Wastewater or other pooled sample
  2. Sequencing reads (FASTQ)
  3. Reference alignment and variant calling — done upstream, offline
  4. Processed SNV table — upload this
  5. Sprint 3 analysis

The site does not process raw reads or call variants, and MAFFT is not used for pooled reads. An optional offline template for read processing is in offline_workflow/.

  • Required: a processed SNV table with sample, reference position, reference and alternative base, frequency, and depth (example). Also accepted: iVar tables, SNV VCF files, and the Fontenele et al. (2021) supplementary workbook.
  • Optional: pooled-sample metadata (dates, sites, coverage), per-position depth or A/C/G/T counts (example), a reference FASTA, a masked-site list, and documented variant profiles (example).
Combined analysis (Sprint 2 + Sprint 3)
  • All files of both analyses above, plus one reference genome FASTA that both sources use (example).
  • Result: every variant is compared across sources by reference position and nucleotide change — shared, one source only, unresolved, or incomparable.
  • The Integrated Example on the right uses exactly these files.

Accepted file formats
  • Sequences: FASTA (.fasta, .fa, .fna), optionally gzip-compressed (.gz). One sequence = possible reference genome; several = individual sequences.
  • Tables: CSV, TSV/TXT (tab-separated), XLSX (first sheet); CSV/TSV may be .gz. Column names are matched flexibly (for example Sample / Sample_ID / SampleName, Date / Collection_Date, Lat / Latitude, AF / Frequency, DP / Depth).
  • Pooled variant calls: standardized SNV tables, combined iVar variant tables, the Fontenele et al. (2021) supplementary SNV workbook, and SNV VCF files (.vcf, .vcf.gz) with allele depths or frequencies.
  • Not accepted as results: raw reads (FASTQ) and read alignments (SAM/BAM/CRAM). Process them first with the optional offline workflow; then upload the variant table or VCF.
