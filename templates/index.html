Integrated Genomic Surveillance

This prototype combines two kinds of genomic evidence: individual (consensus) sequences and pooled samples such as wastewater. Both are placed on the same reference-genome positions whenever the reference is verified, so variants can be compared across sources, over time, and among locations. Results are screening signals; they do not confirm transmission, an outbreak, or the lineage of a mixed sample.

MAFFT aligns sequences within each pathogen and gene/segment group before genetic distances are calculated. With a reference FASTA, each sequence is also aligned to the reference so its differences receive true 1-based reference positions.

When metadata has a location name but no coordinates, GeoNames may estimate them. These place coordinates can be approximate. State-only names such as USA: ND are too coarse for the kilometer cutoff or same-location fallback; their precision is reported in the pairwise output.

Genomic regions come first from metadata, then explicit FASTA descriptions. MAFFT aligns only samples with the same resolved pathogen and region. An unknown region is an error unless you explicitly confirm that every sequence is a complete genome of one pathogen.

Run analysis

Upload individual sequences, pooled-sample results, or both. Cross-source comparison runs only when both are present and share a verified reference. All files in one request must total less than 10 MB; larger processed datasets can be analyzed with run_integrated_analysis.py on your own computer.

1. Individual sequences (optional) Nucleotide (consensus) sequences, for example from NCBI Virus. N, gaps, and IUPAC ambiguity codes are kept as uncallable positions. Accession, pathogen, collection date, location, and host/source. A gene/segment column is optional when FASTA descriptions identify the region.
2. Shared reference genome (optional) Needed for reference-based variants from individual sequences and for cross-source comparison. Its identifier (for example NC_045512.2) must match the pooled table's reference; different labels are never assumed to be the same genome.
3. Pooled samples (optional) Fontenele et al. (2021) Supplementary Table 2 (mmc2.xlsx), combined iVar variants output with a SAMPLE column, or the standardized columns Sample_ID, Reference_Genome, Position, Ref, Alt, Alt_Frequency, Read_Depth. Sample_ID with Collection_Date, Location_Name, Genome_Coverage_Percent (at 10x), Mean_Depth, Latitude, Longitude. Sample_ID, Reference_ID, Position, and Depth or A/C/G/T counts. Shows whether unreported positions were covered; A/C/G/T counts enable the paper's Yue–Clayton PCoA. Signature_Name, Reference_ID, Position, Ref, Alt, Source. Compared as profile overlap only, never as a lineage call.
4. Settings

Run Example Analysis uses explicitly synthetic sequences and sample records, not NCBI records or real outbreaks, with your threshold settings and the same MAFFT-backed pipeline. One example record has a real place name but synthetic sample data and no coordinates so GeoNames can be demonstrated when configured.

Run Integrated Example uses an invented reference, invented individual sequences, and invented pooled samples designed with known answers. It is entirely synthetic.

Thresholds are prototype settings, not universal biological outbreak definitions.
